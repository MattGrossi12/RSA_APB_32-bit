    02 / testbenchs/

    Testbench

    A bancada do topo faz o reset, testa os registradores e executa os cálculos RSA.

    Abrir testbench.sv ↗

    testbenchs/rsa_apb_top/testbench.sv

    01Reset

    PRESETn e CTRL.SRST.
    Espera de 5 clocks.

    02Registradores · {{REGISTER_ROUNDS}} rodadas

    Escrita e leitura de IER, MSG, EXP e MOD.
    Nova leitura para conferir a retenção.

    03RSA · {{RSA_ROUNDS}} operações

    Comparação de RESULT com MSG^EXP mod MOD.
    Checagem de STATUS e IRQ.

    Principais tasks da bancada.
    AtividadeTasks
    Aplicar resetapply_hardware_reset, apply_software_reset
    Acessar o barramentoapb_write, apb_read
    Testar registradorestest_register_writes, check_register_retention
    Executar RSAtest_rsa_operation, wait_rsa_completion
    Comparar valores e mostrar o resultadoscoreboard_check, report_results

    A scoreboard compara os valores esperados com os lidos pelo APB. Para o cálculo RSA, a referência usa exponenciação modular. O plano de teste descreve os vetores e as verificações.

    Bancada do adrec

    Percorre os 4096 endereços de 12 bits, confere o índice e a validade e testa cinco casos com X/Z.

    Abrir testbench do adrec ↗

    As tasks sweep_addresses, check_address e check_unknown_bits verificam o novo bloco. Os bits de byte PADDR[1:0] continuam ignorados; a faixa válida vai de 0x000 a 0x01F.

    03 / scripts/

    Scripts

    Comandos para simular o topo, gerar a cobertura e montar esta página.

    Pasta scripts no GitHub ↗

    Icarus Verilog

    iverilog.sh ↗

    Compila e executa a bancada. Salva o log e o VCD.

    ./scripts/amba_3_apb_rsa_apb_top/bash/iverilog.sh

    Verilator

    verilator.sh ↗

    Executa a mesma bancada e gera os relatórios de cobertura.

    ./scripts/amba_3_apb_rsa_apb_top/bash/verilator.sh

    GitHub Pages

    build.py ↗

    Usa os READMEs, logs e relatórios para gerar os arquivos em _site/. Veja como instalar as dependências e gerar a página.

    python3 scripts/pages/build.py

    Execute os comandos na raiz do repositório. Os dois simuladores aceitam +DATA=DEADBEEF para mudar o dado usado no teste dos registradores. A publicação usa o workflow pages.yml.
